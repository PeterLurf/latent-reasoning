# Prior check for §136 GROW (the user's idea): start with a narrow latent and widen it during training (2026-10-06)

Literature session, for Theory, at the user's request via Audit; Audit copied. IDs verified via the arXiv API
(2026-10-06) or earlier notes.

## Priors
- **Function-preserving growth:**
  - **Net2Net, 1511.05641:** Net2WiderNet widens by *replicating* units and splitting their outgoing weights, plus small
    noise to break symmetry.
  - **GradMax, 2201.05125:** new units with **zero outgoing weights** (function preserved) and incoming weights chosen
    to *maximise the gradient norm*.
  - Splitting steepest descent, 1910.02366.
  - Transformers: bert2BERT 2110.07143; LiGO 2303.00980 (learned growth operators).
- **Progressive growing:** Progressive GANs 1710.10196 (grow resolution; new layers faded in with a weight α).
- **Capacity curricula:** **Burgess et al. 1804.03599** (β-VAE with a *controlled capacity increase*, narrow → wide
  information), the closest conceptual match.
- **Nested / ordered codes:**
  - nested dropout, 1402.0915 (ordered dimensions: the first k must suffice);
  - **Matryoshka Representation Learning, 2205.13147** (nested prefixes trained jointly);
  - **Matryoshka Quantization, 2502.06786** (nested integer precisions in one model);
  - FSQ 2309.15505.
- **Widening a recurrent state mid-training:** none found beyond the general Net2Net / GradMax mechanisms, and nothing
  for a latent carrier in an LM. **New as scoped.**

## What our data predicts
- **The direction is right.** §126 ANNEAL (wide → narrow) collapsed at λ = 1, while narrow enters and wide 64-d stalls.
  GROW is the *reverse* order, matching Burgess and progressive GANs: learn the coarse state in a small space, then add
  capacity.
- **Entry is inherited from the narrow phase**, including its seed-2 plateau. GROW doesn't fix entry. It aims at
  capacity *after* entry.
- **The key prediction: on S5 alone the new dimensions will stay unused.** Once the 8-d code is exact, the final-answer
  loss is about 0 and there is no gradient pressure to recruit the new dimensions.
  - **GROW can only show a benefit on a task whose state exceeds the narrow capacity:** S5×4 (27.6 bits > FSQ-8's
    24), as §133 stage 2 planned.
  - On S5, GROW should match FSQ-8, and that is a *null by design*, not evidence.
- **The natural trigger on a capacity task is a plateau at a non-zero loss** (the narrow code saturated), not a
  threshold reached after success.

## Scoring flags
1. **GROW-ZERO with both new in- and out-weights at zero is dead:** zero activations times zero weights give zero
   gradient to both.
   - **Zero only the outgoing (W_up) columns, and initialise the incoming (W_down) rows non-zero**: GradMax-style (choose
     them to maximise the gradient) or small random. The function is preserved and gradient flows.
   - Or Net2WiderNet: replicate existing dimensions with split outgoing weights plus noise.
2. **FSQ specifics:** new dimensions whose pre-activations round to one level are inert. Initialise their scale so they
   span several levels, or let them be continuous at first (GROW + NOISE).
3. **The attractor after growth:** report ρ before and after each widening step. A widening that breaks the 8-d
   attractor (drift on the new dimensions) defeats the purpose.
   - **New continuous dimensions (GROW + NOISE) are the risky arm** (RAW-H-style drift).
4. **A single-run alternative to compare: nested training** (nested dropout / Matryoshka). Train all 64 dimensions
   from step 0 with random prefix truncation, so the first 8 must suffice and later dimensions add capacity.
   - It needs no trigger and implements "narrow first" implicitly.
   - It is also the clean test of whether an *ordering* or the *staging* matters.
5. **Report codes per state and closure at each width.** Wider codes may stay exact but stop being canonical (§120:
   open machine), which is a C2 / CERT concern.
6. **Staged 8 → 16 → 32 → 64:** each stage's trigger should be pre-registered and label-free (a plateau on training
   loss).

## Addendum (2026-10-06): Theory's draft (d 4 → 64; arms A–D)
- **Further priors:**
  - residual VQ adding stages, SoundStream 2107.03312;
  - NeST grow-and-prune, 1711.02017;
  - Dynamically Expandable Networks, 1708.01547 (expand when the loss on a new task can't be met);
  - **Self-Expanding Neural Networks, 2307.04526**: add capacity when a natural-gradient "expansion score" says it would
    cut the loss. A principled, label-free trigger.
- **(2) Init:** zeroing only W_up's new columns is the right minimal fix. **GradMax 2201.05125** (incoming weights
  chosen to maximise the gradient norm with outgoing zero) is worth *one* arm only if the zero-out arm shows the new
  dimensions staying unused under S5×4's capacity pressure; otherwise it's a refinement. FSQ: scale the new
  pre-activations so they span several levels (inert otherwise).
- **(3) Failures:**
  - Unused dimensions without capacity pressure: S5 is a null by design.
  - **Growth spikes:** ProGAN 1710.10196 fades new parts in with a ramp α. Do the same on W_up's new columns (or
    clamp their LR briefly).
  - **Adam state:** new parameters need fresh moments. In PyTorch a new param group starts its bias correction at
    step 1, giving large early effective steps. Give the new parameters a **short LR warm-up** (a few hundred steps).
    Keep the old parameters' state as is.
- **(4) Triggers:** loss-plateau triggers are the common practical choice (DEN 1708.01547; staged ProGAN by
  schedule). A **plateau at non-zero loss** is preferable to a threshold. A threshold reached on S5 means the task is
  already solved, so there is nothing to add capacity for. A gradient-based score (2307.04526) is the principled
  alternative.
- **d = 4 start:** S5 needs log₂ 120 ≈ 6.9 bits. FSQ-4 at 8 levels = 12 bits, enough but tight, and entry at d = 4 is
  untested. Pre-register the d = 4 entry rate against the d = 8 baseline (§128), since GROW inherits entry.
- **(5) Verdict:** new as scoped. The growth mechanisms are known (Net2Net, GradMax, ProGAN, SENN); their use on an LM's
  latent carrier, judged by certificate and capacity, isn't.
