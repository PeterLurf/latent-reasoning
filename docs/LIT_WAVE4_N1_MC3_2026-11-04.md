**MC3 / doc 01: NARROW. Withdraw "EntNet = closest ancestor".**
- The closest prior is **Fast Weight Memory**, Schlag, Munkhdalai & Schmidhuber 2011.07831 (empirics, plus Theorem B.1). It matches MC3 on all four points:
  - a delta-style write at every step that removes the old association first;
  - two write keys that behave like entity ⊗ relation;
  - multi-hop reads chained over 3 queries;
  - catbAbI, which forces outdated associations to be overwritten.
- Its parent is TPR-RNN 1811.12143 (per-sentence tensor-product writes on bAbI; derivation + empirics).
- Our 11-03 ARCH_UPGRADES note (73f6c972) named EntNet as the nearest prior and missed FWM. That note is corrected here.
- EntNet 1612.03969 has per-entity slots with a gated *additive* update and a single read, so list it as "per-entity slots (additive)".
- Wording for §1: "Per-statement delta-rule writes keyed by entity, with multi-hop reads, are known from fast-weight / TPR memories trained from scratch (FWM 2011.07831, TPR-RNN 1811.12143; EntNet 1612.03969). Not found: such a table written by a pretrained LM at statement ends inside a pass-looped latent reasoner, with later passes' ':' write trained into a by-name update, table use forced by masked text (MASK-GIVEN) and tested causally (row-swap)."
- The other sentences are OK:
  - §2.2 KEY-ALIGN is a design statement; don't label it new.
  - §2.4: cite the capacity result in 2102.11174 §4.
  - MASK-GIVEN: call it "a masked-text necessity test" (cf. MQAR, 2312.04927).
  - ROW-SWAP: cite 2310.17191 and 2609.24635.
  - CTRL-COLON prior: backed by 2402.18668 and 2312.04927 (theorems).
- **Math-backing starting points.**
  - FWM Thm B.1: the written key holds the convex mix (1−β)v_old + βv_new, so MC3's gated form α_se = 1 − s(1−α), β_se = sβ reduces exactly to the identity at s = 0.
  - 2102.11174: at most d_key keys can be retrieved exactly, which bounds the capacity per head.
  - Gated DeltaNet 2412.06464: each write is one SGD step with decay on ‖Sk − v‖², which backs §2.5's α → 1 retention prediction.
- Optional later arm: FWM's two-key outer-product write (entity ⊗ attribute), which beat concatenation in FWM's own ablation.

## 1. Novelty sentences in the doc and verdicts
The doc has few explicit "new / first / no prior" sentences. Its novelty claims are mostly implicit (§1 Question; §9 "closest ancestor"). Each is listed below.

1. **§1 Question (l.14-17), implicit novelty: "DeltaMem as a name-addressable table: pass 1 writes (entity -> value) at every statement end; each later write is a by-name delta update; the question entity reads it back."**
   - Verdict: **NARROW**.
   - Nearest prior: FWM 2011.07831 (Schlag, Munkhdalai & Schmidhuber). It writes at every step with a delta-style update, F += β (k1⊗k2) ⊗ (v − v_old), which removes the old association. Its keys behave like entity × relation. Reads are multi-hop (N_r = 3 chained queries). catbAbI was built specifically so that outdated associations must be overwritten.
   - Also prior: TPR-RNN 1811.12143 (entity-relation-entity tensor-product writes per sentence; bAbI) and EntNet 1612.03969 (per-entity gated slots updated per sentence).
   - Suggested wording: "Per-statement delta-rule writes keyed by entity, with multi-hop reads, are known from fast-weight / TPR memories trained from scratch (FWM 2011.07831, TPR-RNN 1811.12143; EntNet 1612.03969 slots). Not found: such a table written by a pretrained LM at statement ends inside a pass-looped latent reasoner, where later passes' single ':' write is trained into a by-name update and table use is forced by masked text (MASK-GIVEN) and tested causally (row-swap)."
2. **§9 table (l.322): "1612.03969 ... per-sentence entity slots (closest ancestor)".**
   - Verdict: **WITHDRAW "closest ancestor"** for EntNet.
   - EntNet slots use a gated *additive* update with a normalisation, not a delta erase, and a single attention read with no hop chain. FWM 2011.07831 matches MC3 on all four axes: delta erase, per-step write, entity-like keys and multi-hop read.
   - Suggested wording: "closest ancestor: FWM 2011.07831 (delta write + multi-hop read); EntNet 1612.03969 = per-entity slots (additive gate)". Change the FWM row's use from "per-input writes" to "closest ancestor: delta-rule entity/relation writes, chained reads, overwrite needed (catbAbI)".
3. **§2.2 l.88 "By-name update is not hard-wired ... rewarded by the recall loss ... measured as KEY-ALIGN".**
   - Verdict: **OK** (a design statement, not a priority claim).
   - Related: FWM also learns its keys without supervision. Its paper reads one key as an entity and one as an action, but only as an interpretation.
   - KEY-ALIGN as a cosine between the write and update keys was not found as a named diagnostic. Keep it unlabelled (no "new").
4. **§2.4 l.122 "Additive heads ... no exact retrieval and no by-name overwrite".**
   - Verdict: **OK**, but cite the derivation: Schlag 2102.11174 §4. Additive fast-weight capacity is bounded by d_key; past capacity, interference makes retrieval inexact; the delta rule is motivated as the correction.
5. **§1 l.27 / §2.2 l.93 / §2.3 l.112 "Unlike NK ...", "which NK lacked" (necessity via masked values).**
   - Verdict: **OK**. These are internal comparisons.
   - The device of making memory necessary by hiding values from the text has a literature analogue: text-free recall, i.e. MQAR-style queries from the state only (Zoology 2312.04927).
   - Do not call MASK-GIVEN "new". Call it "a masked-text necessity test".
6. **§5 B5 ROW-SWAP (implicit novelty of the row-level causal swap).**
   - Verdict: **OK, no priority claim**.
   - Interchange / patching is standard: binding-ID swaps 2310.17191; KV-record transplant 2609.24635. Cite both as the method's lineage.
7. **§8 / OC: "CTRL-COLON may pack 1-3 givens into the ':' write (6 heads x rank 1)".**
   - Verdict: **OK**.
   - Math backing: Based 2402.18668 gives a recall-vs-state-size lower bound (theorem). Zoology 2312.04927 gives MQAR capacity. Six rank-1 updates per pass bound what one ':' write can store.

## 2. Math backing MC3 can start from
- **FWM Theorem B.1 (2011.07831 App. B).** The update yields (1−β) v_old + β v_new at key k1⊗k2: a convex overwrite. MC3's α_se = 1 − s(1 − α), β_se = s β is the gated-delta analogue; s = 0 is the identity by direct substitution.
- **2102.11174 §4–5.** The delta rule as error-correcting fast-weight writes, plus a capacity argument: at most d_key orthogonal keys are retrievable exactly. This gives the per-head table capacity of 6 delta heads with d_head keys.
- **2412.06464 (Gated DeltaNet).** Online-regression view: S_t = α S_{t-1}(I − β k kᵀ) + β v kᵀ is one SGD step on ||S k − v||² with weight decay. This backs §2.5's claim that every ':' write decays the table by α, and the retention prediction (α → 1).
- **2402.18668 / 2312.04927.** Theorems linking recurrent state size to MQAR recall. These back the OC claim that CTRL-COLON can store only a few givens.
