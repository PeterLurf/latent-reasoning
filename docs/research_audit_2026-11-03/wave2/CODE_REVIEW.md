## Findings (severity order)

### MED-1 hh_hidden / read_vec bypass the NK read (trap 7)
- boxes/inject_aw_eval.py:831-836 `hh_hidden`: `from boxes.deltas5 import fwd_read; h = fwd_read(m.g, m.g.embed(x), m.mem, S)`, docstring "pred ... exactly as dec_logits". For `InjectNK` (nk.py:93-105) `dec_logits` runs `fwd_read_nk`, which adds `W_on (S_n q)` at name tokens; `deltas5.fwd_read` -> `DM.read_fixed` slices only `S[:, :h_add+h_del]`, so the packed NK block (S[:, NB]) is silently ignored (no shape error). The think passes in `hh_dump` (:848) and `hh_dump_inc` (:1166) use `m.pass_aw`, which IS NK-aware, so `P` / `H` / `acc_k8` / `acc_halt` / khalt in part_halthead, part_halthead2, part_halt_inc, part_stab, part_stab_fresh would come from a decoder without the trained NK read, disagreeing with part_acc / part_halt (`m.dec_logits`, :69 / :80).
- boxes/inject_aw_eval.py:303-309 `read_vec` and :332-335 (part_probe): `read1|v1` and the `read_fixed` cross-check are the DeltaMem read only; for an NK model the probe silently omits the NK channel (and the `read_vec_check_rel` assert cannot see it).
- Impact: latent. The only NK runs (boxes/runs_fsq/pilot_nk_s1, pilot_nk_s1_gtime*) ran `--eval_parts acc,nk_pilot` (args.json), both NK-aware. §262 is parked (Note 262-3: NK binding unused), §263+ cells are `--nk 0`. Becomes HIGH the moment halt* / stab* / probe run on an `--nk 1` model.
- Repro (CPU): build InjectNK with a non-zero `W_on`, any S with a non-zero NK block: `hh_hidden(m, S, ch, dev)[1]` vs `pred_of(m.dec_logits(S, ch, dev))` differ. Fix idea: `h = m.fwd_read_nk(x, S) if hasattr(m, "fwd_read_nk") else fwd_read(...)`; part_probe should assert `not hasattr(m, "nk")` or add the NK read.

### MED-2 Eval-only wrappers write the drain's done marker even when the eval failed
- scratch/s257_guarded.py:58 and scratch/s259_guarded.py:63: `json.dump({"eval_only": True, ...}, open(out + "/log.jsonl", "w"))` runs unconditionally after `rc = subprocess.call([... boxes.inject_aw_eval ...])`; host_shas.json follows (`manifest(out)`). A crashed eval (rc != 0) still lands as "done" (log.jsonl + host_shas present); only the wrapper's exit code carries the failure. In s259 `rc = rc or subprocess.call(run_long)` (:61) also silently skips run_long on a failed parts eval and still writes the marker.
- Impact: §257 / Note 257-2 / §259 eval-only cells; scorers fail loudly on a missing eval_*.json so no wrong verdict, but a requeue watcher keyed on log.jsonl will not re-run the cell (see memory "watchers exit silently").
- Repro: `--parts nonexistent --device cpu` locally -> log.jsonl stub appears. Fix: write the stub only when rc == 0.

### MED-3 HOLD-INC penalises the NK block (design interaction worth a $0 read, not a bug)
- boxes/inject_aw.py:159-199 `hold_step` uses `state_n(S)` (:154-156, Frobenius over ALL blocks) and `m.write` = `InjectNK.pass_aw` (nk.py:79-91), so from `--hold_start` (500) `L_inc` penalises `||S_pen - S_{t-1}||^2` including `S_n`. The NK write is `S_n <- S_n - (S_n k) k^T + v k^T` with `v = W_vn ln_w(h_11 at ':')` (nk.py:60-61, :90): idempotent across hold passes only if `v` is the same at every hold pass, which it is not (h_11 changes with S). The cheapest way to zero the NK hold increment is `W_vn -> 0`, i.e. the penalty pushes against the NK value write itself. The nk.py docstring (:1-2) says "every consumer of S ... sees it" as a design choice; gate_s269 step0 reports NK full-S hold stats "by design" (:9-10). Note 262-3 reports "NK's binding was unused (dropped)" — consistent with this pressure. Suggested $0 read on pilot_nk_s1: `||W_vn||` / `nk_block_norm` over training vs CTRL; if a later NK revival is considered, exclude S[:, NB] from the hold penalty (or penalise the NK block with its own lambda).

Impact: conds / conds_mass["d4k6"], def. Fix: correct the def string (a Note-level correction; no rerun needed).

### LOW-1 NK construction consumes the global torch CPU RNG after the run seed (trap 5)

The docstring (:14) claims "the trunk / torch RNG stream of the run is the CTRL arm's". The CPU stream differs between NK and CTRL after construction; the CUDA generator is untouched.
