## 0. Mechanics the alternatives rest on (verified in code, not in notes)

- **M1 The per-pass function is pass-index-blind by construction.** `--cache_lower` computes blocks 0-5 once per distinct input (deltamem.py:264-275; inject_aw.py:370); pass t's input is text + cue S_min(t,d) (inject_st.py:5, 44-46). The only channel that can carry "which pass this is" is S itself. So "passes 5-7 compute although only passes 1-4 were ever trained to compute" is expected unless S stamps a counter; C2-by-depth is therefore mostly a memory and selection question, not a "more thinking" question.
- **M2 Every causal C1 gate stops at d 4.** `part_swap_kd` and `part_lp5h` loop `range(3, d_max + 1)` with d_max 4 (inject_aw_eval.py:395, 513); NOT-DECODER is d 4 at K' 2. No swap, ablation or donor test exists at d 5-8, the depths where C2 is claimed.
- **M3 SWAP-MID's follow_U pools two counterfactuals.** U = {cf_a(t), cf_b(t)} (inject_aw_eval.py:392-410); cf_a = the chain continued from ALL donor states 0..t, cf_b = only S_t from the donor (inject_ow.py:117-124). follow_ca and follow_cb are stored separately per d.
- **M4 LP5 is a ≥ 0.30 drop, not "to chance".** Binding at K' = d pooled over d 3-4 (inject_aw_eval.py:527); `mean_at_t` is stored.
- **M5 The hold penalty covers passes d+3..K plus one far pass T_far ~ U{16..40}** (inject_aw.py:159-199; args hold_far_lo/hi 16/40). Passes d+1, d+2 are unpenalised. K' 128 is a 3-8x extrapolation of the trained far horizon, not 16x.
- **M6 bun was never evaluated on the distractor families.** bun_s1 args `eval_parts = acc,swap_kd,lp5h,cue_only,ws_deep,halthead`; no `insert_ho` file exists in boxes/runs_fsq/bun_s1/. "Content step selection" on the SOTA model is inherited from dch (sota_arch.json limits line 6 says so), after 8k more steps with a new loss.
- **M7 The decoder adds one hop** (Note 264-4: d 4 at K' 3 = 1.000). Every "d" in the scorecard is d-1 latent hops plus a decoder hop; the C5 halt at d-1 follows from this, not from a decision.
- **M8 Ops are bijections mod 11** (NORTH_STAR_GAP §2.3; values mod 11, prime). Under strictly serial use, a wrong v_{t-1} in S can never produce a correct v_t at pass t; any recovery after an error is either a readout-only error or recomputation from the text. This makes a sharp $0 serial test possible from stored per-pass readouts (see C1-A2).
- **M9 Stored files that the $0 reads below need** (all already in bun_s1 / bun_s2): eval_ws_deep.json (ws_pred per pass 1..8 and v per pass, d 5-8; inject_aw_eval.py:1111-1119); eval_stab_fresh.json (pred at K' 0..14, ans, sig, d 1-8); eval_acc.json (per-item pred at every K' 0..KMAX plus sig); eval_lp5h.json (intact and mean_at_t per item, d 3-4); eval_swap_kd.json (follow_ca / follow_cb / stay_own per d, per item); eval_long_k128.json (acc, s_norm, s_cos per K', per-item preds, d 1-6).
