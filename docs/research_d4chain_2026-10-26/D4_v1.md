## 1. Change (fixes 2, 3, 5)
- New OW.Stream kwarg `mul_s_p3` (default 1.0 = current behaviour). **It acts at d = 3 only.**
  - With probability 1 − mul_s_p3, a d = 3 program drops the forced mul_s (ts := None, so all three steps are regular ops from OPS_REG).
  - The coin is drawn **once per program, before the restart loop, and only when mul_s_p3 < 1.** At 1.0 there are no extra rng draws (flags-off bitwise gate on the stream).
- **Training stream only:** mul_s_p3 0.5 at inject_aw.py:150. It is never put in OWKW.
  - Calibration (mem.norms), memcheck, TEST2, transfer, pairs, swap, lp5h and probe streams are untouched.
  - Gate: the set shas equal aw_plaw4_s1's args.json, and the eval items' sigs equal aw_plaw4_s1's.
- Effect: P(mul_s | pass 3) goes from 1.0 to ≈ 0.5 at d 3 (≈ 0.46 at d 4, unchanged); pooled over d 3–4, from ≈ 0.73 to ≈ 0.48. d 4, and so pass 4's training, is unchanged.
  - Log the realised shares (d 3 mul_s share over the first 10k training items) in the run record.
- **Disclosed side effects (fix 4):** skipped d 3 items have S_1 or S_2 < 2 about 8% of the time each (the mul_s rejection rule no longer applies), and their _v ops add a given sentence. The test sets are unaffected.
- **Arms:** LAT-AW d4d_plaw4_s1, CD-AN d4d_pcd4_s1; one RTX 3090 each. Args diff vs aw_plaw4_s1 / aw_pcd4_s1 = {mul_s_p3 1.0 → 0.5} (+ run name).

## 2. Mechanism note (fix 7)
- InjectAW has no pass embedding (inject_aw.py:45–54). The pass index can only come from the memory state (write count / content) and the cue entity.
- Audit's oracle (scratch/audit_d4_chain/diag.json d_oracle): with prior values given in the text and no state, pass 3 is 0.844 and pass 4 is 1.000. With the real memory, pass 3 copies v_{t−1} on 0.49 of items. Both count against H-CAP.
- In C1, the shortcut's d 3 training accuracy under the new mix is ≈ 0.5 + 0.5 × 0.09 ≈ 0.55 (fix 8).
