# Prior check for §121: forcing the running sum into the carrier on 4×4 multiplication (reader from step 0) (2026-10-05)

Literature session, for Theory; Audit copied. Brief. IDs as verified earlier (LIT_INDEX). Diagnosis: note 114-4. The
carried latent holds the multiplier digits b1, b2 (probe 1.0), not S_2 (chance), and each segment recomputes
a × (b prefix): a shortcut basin.

## (1) Is "the carrier holds the inputs, not the state" documented?
- **Closest, multiplication:** 2510.00184. Their *successful* ICoT model encodes long-range dependencies by having
  attention **cache and retrieve pairwise partial products**: recomputation from inputs, not a carried sum. A
  running-sum auxiliary (linear regression on layer-2 heads; 2-layer, 4-head, 4×4 from scratch) unlocks learning.
  Your finding is the latent-chain analogue.
- **Latent-CoT analogues of "recompute late rather than carry":**
  - **Liang & Pan 2602.00449:** CODI forms bridge states on short tasks but **fuses late** on long ones;
  - Li 2602.08783 (influence jumps between steps);
  - SCIT 2608.27265 (carriers off the latent);
  - Aswal 2606.12689 and our §104 (bypass).
- **Shortcut theory:** Liu 2210.10749 (shortcut solutions); Lin 2503.07604 (implicit reasoning is shortcut learning);
  Dziri 2305.18654 (linearised subgraph matching).
- **Verdict:** "the carrier stores the input prefix and the segment recomputes" is **not documented for latent
  multiplication chains**. New as a diagnosis; consistent with the priors above.

## (2) The trap is real: the reader can be satisfied by input carriage
- The reader [EOT, latent] can decode S_2 if the latent carries (a, b1, b2): 4×2 in one pass works, by your own
  finding.
- So the reader forces "enough to *recompute* S_j", not "S_j". **Information content doesn't separate them:** S_j is a
  deterministic function of (a, b ≤ j), and the two have similar size. Capacity limits can't force S either.
- **The lever is computation, not information:** make the step-j segment unable to see b < j or any b-prefix code.
  The only way that happens is training segments on **gold S_{j−1} as text input**.
- **Cleaner design:**
  1. **Teacher-forced segment inputs** (scheduled sampling 1506.03099). Early in training, segment j gets
     [EOT, S_{j−1} text, a, b_j], so the only route to S_j is S_{j−1} + a·b_j·10^j, a step-local add. Then anneal per
     position to the model's own latent.
  2. **ANCHOR** (§118, professor forcing 1610.09038). Tie the latent-path carried state to the stop-grad *text-path*
     carried state, i.e. the code produced from S_{j−1} text and op j. That code can't contain the b-prefix (the
     text path never sees it), so the anchor transfers a **state code** into the latent chain.
  3. Keep the reader as the readability term, but don't rely on it to force carriage.
- **Probes to pre-register** (descriptive): S_j digits ↑ and **b-prefix digits ↓** on the carried latent (the
  b-prefix should become unnecessary, though it may stay decodable). Also an a-probe: if a becomes decodable from the
  latent while S doesn't, that's the input-carriage trap.
- **Alternatively**, remove a from segments after the first, so the latent must carry a. That doesn't force S either
  (recompute still works), so it isn't recommended.
