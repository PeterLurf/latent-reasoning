# Prior check for §110b: random given start states for training (fixing §110's restart gate) (2026-10-04)

Literature session, for Theory; Audit copied. Brief. IDs as verified earlier (LIT_INDEX).

## 1. Is training on random given start states standard, and is it final-answer supervision?
- **Standard in entity / box tracking:** Kim & Schuster 2305.02363 and Prakash 2402.14811 (the initial box contents are
  given in text, then operations, then a query about the final state). Our §66 boxes use random start arrangements.
- **Group word problems usually start at the identity:** Merrill 2404.08819, DeltaProduct 2502.10297, Liu 2210.10749
  (a fixed start state q₀).
- **The closest rationale for why random starts help length generalisation:** Ruiz & Gu 2507.02782 (initialising
  recurrent states from *other sequences' final states* fixes unexplored-state failures). Random given starts are the
  input-side version of that state coverage.
- **Final-answer supervision: yes.** The start state is input. The target is s·w, and no intermediate state is
  labelled. For problems of length ≥ 3, random starts leak no step labels.

## 2. Does it change the C4 qualification? Yes, it strengthens the footholds, so state it
- Length-1/2 problems from random starts label **(s, a) → s·a for arbitrary s**, i.e. Cayley-table entries across the
  whole state space. Identity-start short problems label only e·a = a and e·a·b.
- So "≤ 5% short problems" now means **≤ 5% short problems over random starts: full-table footholds**, a much richer
  supervision than §103's.
- **Wording:** "C4 qualified by ≤ 5% short problems with random given starts".
- Also report the fraction of distinct (state, op) transitions directly labelled by short problems, to make the
  foothold size explicit (cf. §85's p).

## 3. Risks
1. **Start-distribution shift at test.** The identity is one of the random starts (1/120 per problem), so it is in
   distribution as a start, provided the test input carries the identity start **in the same text format**. If the
   protocol test omits start text, that is a format shift. Write the identity explicitly.
2. **Leaning on the start text** is intended. Chunk-start checkpoints at test are already text states, so the restart
   gate now tests exactly the training format. That is the point of the fix.
3. **The gate's correlated-error caveat (LIT_S110_SELFTRAIN) still holds:** chain and restart share weights. Random
   starts make the restart competent; they don't make it independent.
4. **The C1 scoring is unchanged:** masked fork plus donor USE at j−1 → j.
