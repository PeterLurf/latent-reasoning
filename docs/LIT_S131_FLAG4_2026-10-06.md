# Prior check for §131: FLAG4, a post-curriculum-step progress rule for "escape without learning" (2026-10-06)

Literature session, for Theory; Audit copied. Brief. IDs verified via the arXiv API (2026-10-06).

## (a) Priors
- **Learning progress after curriculum steps as a control signal:**
  - Graves et al. 2017, *Automated Curriculum Learning*, 1704.03003 (learning progress as the reward for choosing
    tasks);
  - Matiisen et al., *Teacher–Student Curriculum Learning*, 1707.00183 (the slope of the learning curve per subtask
    drives curriculum choice).
  - These use progress to *schedule* tasks, not to *kill runs*.
- **Run triage:** Dodge 2002.06305, Hyperband 1603.06560, Domhan (IJCAI'15). These use loss curves, but not tied to a
  curriculum boundary.
- Our §130 (an active-units marker) and the 123-3 flag.
- **Verdict:** a stage-conditioned triage rule ("no descent within N steps after a curriculum step ⇒ restart") is **new
  as scoped**. Cite TSCL / Graves for "learning progress after a task change" as the signal.

## (b) Small losses: yes, add an absolute floor
- A ratio rule is scale-free, so at near-zero losses (MOD / RDFA / FF already solved by 2k) noise of 0.01 can make
  loss(4k) ≥ 0.9·loss(2.6k), a false positive on a learner.
- **Floor relative to each family's null:** FLAG4 only if loss(4k) > c·ln(K_family), where K is the answer-class
  count: ln 120 for S5, ln 5 for CYC / MOD, the RDFA output count, ln 2 for FF reads.
  - c ≈ 0.25 mirrors 123-3. Or use loss(100) as the null, as 123-3 does.
  - That makes the rule comparable across families, which matters for the task-agnostic claim.
- Also compare **windowed means** (e.g. mean over 3.8–4k vs 2.4–2.6k), not single logged points, to avoid spike noise
  at the curriculum switch.

## (c) Precision ≥ 0.9 at ≥ 5 flagged runs
- At n = 5, ≥ 0.9 means 5/5. The exact 95% lower bound is about 0.55 (Clopper–Pearson). That is weak evidence that the
  rule won't kill learners.
- Report the CI, and keep accumulating flagged runs across §128 / §129. Treat "deployable" as conditional on, say,
  ≥ 10 flagged with 0 false positives (lower bound about 0.74).
- **Selection caveat for the out-of-sample set:** it contains only *full* runs. Runs restarted at 2k (123-3) are
  excluded, so the evaluated population is pre-filtered. State it, since FLAG4's precision is "among runs that passed
  the 2k flag", which is its intended use.
- **The 3.2-basin misses:** a second rule targeting them (e.g. final-plateau detection at L_max 8–16) is a separate
  registration. Keep them as a reported miss class here, as you plan.
