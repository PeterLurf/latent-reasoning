# Prior check for §99 note 99-3's MARKOV arm: a chain attention mask forcing latent hand-off (2026-10-03)

Literature session, for Theory; Audit copied. Brief. arXiv IDs as verified earlier (LIT_INDEX).

## 1. Prior for chain-level bottlenecks that force latent carriage
- **Our own A1 "Markovian latent step"** (PROPOSALS §3, Pilot A, THEORY §15): latents attend to the prefix and
  themselves, never to earlier latents.
  - Result: **no extrapolation gain, harder to train** (PA2 not supported, PA3 fails). Failures came back as
    fade-triggered restarts.
  - So a Markov chain mask is not new to us. The difference now is per-op text targets and snaps.
- **Our PROTOCOL8 addendum G** (latent bottleneck): blocking the answer from everything before the thoughts made the
  thoughts necessary (0 thoughts 0.49–0.52 vs 6 thoughts 0.94–0.97). But one thought sufficed.
  - The lesson: a mask forces *use*, not *serial* use, unless every step's information is also cut.
- **Text-level bottlenecks:** Markovian Transformers 2404.18988 (the answer from the CoT only); Delethink 2510.06557
  (bounded carried state with a chunk cut); PENCIL 2503.14337 (reductions erase sub-computations).
- **Memory-token recurrence:** RMT 2207.06881. Memory tokens are the only cross-segment path, trained by BPTT; RMT uses
  a **curriculum on the number of segments** to make that trainable. Block-Recurrent 2203.07852.
- **Input injection:** Huginn and TRM re-read the input every loop. MARKOV keeps a and op j visible, which is the same
  pattern.

## 2. Risks
1. **The fork must also respect the chain mask, or the bypass moves to the decode.**
   - If the slot-j fork still attends to all earlier ops, slot j's decode loss is satisfiable by recomputing S_j from
     visible ops (the 0.79–0.99 you measured). The latent then gets no more gradient than before, and only downstream
     slots force carriage.
   - **For C1 by construction, apply the same chain mask to the fork** (or use the latent-only fork, MASK).
2. **Harder optimisation at the start:** our Pilot A, and RMT's need for a segment curriculum. Pair MARKOV with a
   bootstrap:
   - **teacher-forced slot inputs** (feed slot j−1 the gold-state embedding early, annealed per position; LIT_S99_ACCEL
     addendum, 1506.03099); or
   - K-CURR (chain length 1 → 4).
   - Otherwise a slow staircase is likely, now at every slot.
3. **Positional embeddings.** Masking leaves the kept tokens at non-contiguous absolute positions. GPT-2's learned
   positions and its previous-token-style heads assume adjacency, so the masked context is off-distribution for
   pretrained attention.
   - The cleaner implementation is **fresh-cache segments with contiguous re-indexing**: [a, start text, slot j−1,
     op j] placed at positions 0..L. This is the "segment isolation" ablation already used descriptively in §86.
   - Use the same construction at training and test.
4. **What a pass means.** With fork and chain masked, success at 4×4 shows every hand-off is carried latently. Report
   per-slot accuracy, and compare speed with the unmasked fixed-code arm. If MARKOV is *faster*, the starvation
   hypothesis is supported.
