# Prior checks: §171 READ-SLOTS (learned slots reading a once-encoded input, DeltaMem across passes) and §174 MULTI-TASK INJECT (2026-10-09)

Literature session, for Theory; Audit copied. IDs verified via arXiv abstract pages (2026-10-09).

## §171 READ-SLOTS: M = 8 learned slot tokens attend to a once-encoded input KV of pretrained GPT-2 per think pass; DeltaMem is the only cross-pass state
**Is there a close precedent on a *pretrained* LM (not from scratch, as Perceiver / RIN are)? Partly, in pieces. Not as scoped.**
- **Learned queries reading frozen encodings, attached to pretrained LMs (single pass, modality bridging):**
  - Flamingo's Perceiver Resampler 2204.14198 (learned latent queries cross-attend to frozen vision features; a frozen LM consumes them);
  - BLIP-2's Q-Former 2301.12597 (32 learned queries over a frozen image encoder into a frozen LLM).
  - This is the closest *mechanism* (M learned queries over a once-computed frozen KV), but it's one pass and not recurrent.
- **Learned memory / summary tokens over text in pretrained LMs:**
  - Gist tokens 2304.08467 (prompt compressed into the KV of a few learned tokens);
  - AutoCompressors 2305.14788 (summary vectors produced per segment and **carried recursively across segments**, from pretrained OPT / Llama);
  - ICAE 2307.06945 (memory slots from a pretrained LLM);
  - RMT / ARMT (memory tokens; ARMT on GPT-2).
  - These read *new* segments each step, not the same encoded input repeatedly.
- **State across loop iterations of a pretrained looped LM:** MELT 2605.07721 (fine-tuned from pretrained Ouro).
  - It keeps **one KV cache per layer, shared across loops and updated by a learned gate**.
  - The closest "persistent gated state across think passes" on a pretrained model, but within a looped LM, without separate slots.
- **Retrieval over cached KV:** Memorizing Transformers 2203.08913 (kNN over cached keys / values).
- **Not found:** a pretrained LM where a few learned slots **re-read the same once-encoded input KV on every think pass**, with a fast-weight memory as the
  only cross-pass state. **New as scoped.**
- **Design notes:**
  - **Init the slot queries from real token embeddings** (or GPT-2's mean embedding) rather than random. Q-Former and Resampler queries are trained
    from scratch against a frozen LM, and need lots of data to align.
  - **The read map is a C7 asset.** Log the slots' attention over input tokens per pass. A digit / edge sequence across passes is direct evidence of
    a learned schedule.
  - **Bypass:** the decoder must see only the slots / memory, not the encoded input (as GEN-M-MASK). Otherwise the answer can read the input directly.

## §174 MULTI-TASK INJECT: one GPT-2 + DeltaMem-R; 50/50 mix of 4×n multiplication and Feng mod-11 expressions; no task flag; K8; FINAL only
**Is "one recurrent latent harness, several tasks, no task flag, per-task K ablation" new? Close precedents exist for parts of it.**
- **Multi-task with adaptive or recurrent depth, plus per-task depth analysis:**
  - **Universal Transformers 1807.03819:** trained **"single" and "joint" on all 20 bAbI tasks** (joint = one model, no per-task model), with ACT
    ponder times analysed per task. **That's the classic precedent for one recurrent-depth model across tasks with per-task depth behaviour.**
  - **Huginn 2502.05171:** pretraining-scale mixed data. **"Saturation is highly task-dependent": easier tasks saturate at fewer recurrences.** ARC
    with more few-shot examples uses more (8–12 → 20 → 32 iterations). That's a per-task K curve on one model.
- **Multi-task algorithm learning with interference measured:** Ibarz et al. 2209.11142, "A Generalist Neural Algorithmic Learner".
  - One processor trained on all 30 CLRS algorithms.
  - **"It is possible to effectively learn algorithms in a multi-task manner, so long as we can learn to execute them well in a single-task
    regime."** It reports a full multi-task ablation, with stabilisation changes needed.
  - **But it has per-algorithm encoders and decoders (an implicit task identity).** No-flag operation is not tested.
  - Veličković 1910.10593: a shared processor across graph algorithms; multi-task transfer helped.
- **Not multi-task:**
  - Fan 2409.15647 trains **one model per task** (per-task heads and depth in its hyperparameter table).
  - Coconut, CODI and PCCoT train per dataset.
  - TRM / HRM: one model per puzzle.
- **General interference / gradient conflict:** PCGrad 2001.06782 (gradient surgery). A remedy if one task degrades.
- **Verdict:** new as scoped, as the combination: a pretrained LM, a memory-only cross-pass state, plain-text task identification (no flag), and
  per-task THINK-NECESSARY / K curves.
  - The closest precedents are UT-joint (bAbI), Huginn's task-dependent saturation, and the CLRS generalist (which has implicit task encoders).
- **Expectations and flags:**
  1. **Interference:** CLRS suggests multi-task ≈ single-task once each task is learnable alone, but with some per-task drops. The ±0.02 tolerance
     is tight. Pre-state what a drop beyond it means (capacity vs gradient conflict). Log per-task gradient cosine (the PCGrad diagnostic) cheaply.
  2. **Per-task K curves are expected to differ** (Huginn, UT ponder). Report accuracy vs K for each task, not only at K8.
  3. **The cross-task memory swap (C7):** a multiplication state injected into an expression item tests whether state *type* is task-specific.
     There's no precedent for this. It's new and cheap.
  4. **Curriculum asymmetry:** n 2..5 vs 1..8 have different difficulty schedules. Sample so neither task's hardest stage dominates late training.
