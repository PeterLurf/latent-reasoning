# Prior check for §155 DELTA-R: write-after-read DeltaMem (read at block 6, write from the top) (2026-10-08)

Literature session, for Theory; Audit copied. Brief. IDs verified via arXiv abstract pages (2026-10-08) or earlier notes.

**Verdict:** the principle is known (top-down / write-from-the-top recurrence). The combination is new as scoped: a matrix associative
memory (additive + gated-delta) read mid-stack and written from the top, as a pretrained LM's only cross-pass channel, tested by
state edits. Note 147-4's finding (writes from the read depth, with a single memory layer, are a fixed function of the input) is a
real structural gap that the multi-layer memories below avoid by construction.

## (1) Write-from-the-top precedents
| Model | State | Written from | Read at | Difference from §155 |
|---|---|---|---|---|
| Feedback Transformer 2002.09402 | per-step vectors (a learned mix of *all* layers) | all layers, mixed | every layer at later steps (attention) | vector memory via attention; from scratch |
| RMT 2207.06881 | memory *tokens* | **last-layer outputs** of the memory tokens | input (layer 0) of the next segment | vector tokens; read at the bottom, not mid-stack |
| Memformer 2010.06891 | a memory slot matrix | a memory writer reading the encoder's *top* output | the next segment's encoder, via cross-attention | slot attention, not a delta / additive associative store |
| TransformerFAM 2404.09173 | feedback-attention-memory tokens, per layer | the **same** layer | the same layer, next block | layer-local feedback; retrofit to pretrained |
| Block-Recurrent Transformer 2203.07852 | state vectors, LSTM-gated | the recurrent layer itself | the same layer | same-depth; from scratch |
| ARMT 2407.04841 / Infini-attention 2404.07143 | an associative (linear-attention) memory **per layer** | each layer's own K / V | the same layer, next segment | **recurrent anyway:** layer ℓ's write depends on lower layers' memory reads in the same segment. §147's *single* memory layer, written from its own input depth, lacks that path, hence 147-4 |
| T²MLR 2607.15178 | the previous token's cached mid-layer vector | a middle layer | an earlier layer | write above read (the same topology as §155); vector, per token |
| Coconut 2412.06769 | the last hidden state | the top | the input | vector |

- **147-4 has a literature reading.** Same-depth writes become recurrent only when several memory layers stack (ARMT, Infini-attention).
  With one memory layer, write-from-the-top (RMT, Memformer, T²MLR) is the standard fix.

## (2) Stability of BPTT through 6 blocks × 17 passes (an effective depth of about 100 layers)
- **The new risk is a feedback loop.** Input-only writes couldn't amplify. Write-after-read can:
  - a read feeds the top residual, which feeds the next write;
  - no-decay additive heads have no forgetting, so norm growth compounds across passes.
- **Remedies to pre-state:**
  1. **L2-normalised keys** (standard in DeltaNet 2406.06484 / GDN, needed for delta-rule stability), and **bounded values** (LN or
     tanh on v from the top residual).
  2. **Gate init:** the gated-delta decay α near 1 (the carry-over bias, as an LSTM forget-gate bias); β small at init.
  3. **Function-preserving migration:** write = (1−γ)·write_from_block6 + γ·write_from_top, with γ ramped 0 → 1 (the ProGAN / §136
     fade-in). The run then starts *at* §147's working solution instead of an empty memory. Without it, the top-write projections
     start untrained and the memory is initially uninformative, which is a re-entry problem.
  4. **Gradient clipping** (global norm) and **truncated BPTT as a fallback only**:
     - truncation lowers how well loops are trained (φ 0.46 → 0.38, 2604.21106);
     - Block-Recurrent and RMT truncate for memory reasons, not by choice;
     - at 17 passes full BPTT is affordable; pre-state full BPTT with clipping.
  5. **Log per pass:** the memory norm, the write-norm ratio and ρ.
     - **ρ is now meaningful for DeltaMem.** Under input-only writes the state had no dynamics, so any earlier ρ was trivially
       input-driven. Re-read old ρ values with that in mind.
  6. **SHIFT-R's per-column reset of the additive store** bounds accumulation. It's the memory analogue of a "flush", and the right
     guard.

## (3) Causal "edit the latent state, check it propagates through later computation" precedents
- **Interchange interventions / causal abstraction:** Geiger et al. 2106.02997; DAS 2303.02536 (aligning a causal variable with a
  distributed representation, then intervening).
- **World-model edits that propagate:** Othello-GPT 2210.13382 (edit the board representation; later move predictions follow);
  Nanda et al. 2309.00941 (linear board-state edits).
- **Recurrent-state interventions:** Csordás et al. 2408.10920 (interventions in GRU hidden states; "onion" non-linear representations,
  so linear edits can fail); Mamba activation patching and editing 2404.03646.
- **Ours:** donor SERIAL is a whole-state interchange. The **rank-1 carry edit** is a DAS-style intervention on one causal variable (the
  carry) in a recurrent memory. Testing its propagation to the column after next is new in this setting.
- **Two cautions:**
  - (a) **Find the carry direction on held-out data** (DAS or a probe fitted on held-out items), not on the items scored.
  - (b) A **null edit** (a random rank-1 edit of the same norm) and **§154 SHIFT** (input-only writes) are both needed: the second shows
    propagation is impossible without recurrence, and the first shows it isn't norm damage.
  - Csordás's onion result means a failed linear edit doesn't prove absence. Report it as "not linearly editable" rather than "not
    carried".
