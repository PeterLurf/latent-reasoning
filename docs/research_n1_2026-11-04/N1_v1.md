## 3. Task and generator (build spec in §10)

### 3.1 Item law (`boxes/so_words.py`, new)

People: n ∈ {3, 4, 5} drawn from `NAMES_SO` = `NAMES` (`nested_words.py` 33-34, 40 single-token names) minus {"Eve", "Bob"} (F12a: both are BBH names) = 38 names. Family f ∈ {balls, books, presents, partners, positions} (BBH's five), n distinct objects, initial bijection h_0, asked object o*, m swaps (a_t, b_t) uniform over unordered pairs. State S_0 = h_0(o*), S_t = τ_t(S_{t−1}) with τ_t the transposition (a_t b_t). answer = S_m; `values` = [S_0 … S_m]; `k_touch` = #{t : S_t ≠ S_{t−1}}; `people_ids` = the item's n name tokens; `d` = m.

### 3.2 Render

- **NUM** (50%): "… At the start each holds one ball: Ann has the red ball, … Swap 3: Kim and Ann trade balls. Swap 4: …". **Offset labels (F3):** the m swaps carry consecutive labels o+1 … o+m with o ~ U{0 … 12 − m} per training item, so every label 1-12 appears in training at m ≤ 4 (G0 histogram). TEST cells use o = 0 (labels 1 … m) unless named OFFSET.
- **ORD** (50%): "First, … Then, … Finally, …" (BBH-shaped; no labels).
- Frames: ≥ 4 paraphrases per family for setup and swap verb; frames 0-3 train, 4-5 TRANSFER; none shares a 13-gram with the 750 BBH inputs (G0).

### 3.3 Cues and targets (`boxes/inject_so.py`, new)

- **SI (main):** pass t input = [EOT] + enc(" " + text + " After swap {L(min(t, m))}, who has the {o*}? The answer is:"), L(s) = o + s (NUM) or s (ORD). Passes t > m repeat the swap-m cue (hold semantics, unchanged `hold_step`, `inject_aw.py` 159). Every label is one GPT-2 token (" 1" … " 12", checked), the object phrase is fixed per item, so all pass inputs share one padding (the assert at `inject_st.py` 78).
- **EN (descriptive comparator, 1 seed):** " After {a_t} and {b_t} trade, who has the {o*}? The answer is:".
- Write source = the ':' token (`InjectAW.pass_aw`, `inject_aw.py` 47); decoder [EOT] + text + " The answer is:" (as `tok_ow`'s dec, `inject_ow.py` 63-71).
- **Aux target** R_step[t] = "After swap {L(t)}, {S_t} has the {o*}." (family verb: has / is dancing with / is playing). **vidx = the position of S_t's name token**, asserted unique in the sentence for every family (F5; `tok_ow`'s `q.index(HAS_TOK) + 1`, `inject_ow.py` 70, points at " the" and raises for the two families without " has"). G0 asserts `dec(aux[vidx]) == " " + S_t` on 20k items.
- **`tok_so` does not route through `tok_st`** (F14): `tok_st` runs the G-CUE loop for any cue ≠ "none" (`inject_st.py` 52-57) and reads `it["unit"]` / `names.spine` (`cue_str`, 44-46). G5 covers it.

### 3.4 Value readout

`VAL_IDS` = the 38 `NAMES_SO` tokens replaces `NUM_IDS` (`nested170.py` 20) at every site: `inject_aw.py` 138, 363, 378, 389, 417, 424 (F14 corrected list) and `inject_aw_eval.py` 33, 41, 321, 670, 768 (incl. the hard-coded width 11 → len(VAL_IDS)), 772, 777. Training CE stays full-vocabulary on the target token (as `loss_reg`, 363 / 405). **Every eval readout is the argmax over the item's own `people_ids`** (helper `pick(lg, it)`, new; G1 / G5 list it). BBH readouts use first BPE tokens (distinct for the 7 BBH names, checked: " Gertrude" → 4 tokens, first " G").

### 3.5 Splits

Train: n ~ U{3,4,5}, m ~ U{1..4}, NUM / ORD 50/50, families all, frames 0-3, offset labels. TEST (held out by `sig`, excl ∩ train = ∅): 500 items per (n ∈ {3,4,5}, m ∈ {1..12}, mode); **n 5 m 8 NUM and n 3 m 8 NUM enlarged to 1,500** (F7: M5 strata, X2 power). TRANSFER = frames 4-5 at n 5 m 1-8. OFFSET cells: n 5 m 4 NUM with o = 8 (labels 9-12). BBH: the 3 × 250 public items (fetched at build, sha recorded; repo licence MIT).

**BBH rendering (F12b, pre-stated):** strip "At the end of the …, X has the" and the "Options:" block; append the SI cue " After swap {m}, who has the {o_j}? The answer is:" per option o_j, m = the parsed swap-sentence count; answer = argmax_j of the ':' logit at pass m (K′ = m) of X's first BPE token. DIRECT-OF: the same, one pass on dec = text + question + " The answer is:". TEXT-CoT: the same per-option question, greedy chain, then the logit of X's first token at the answer position. One rule, no ties (exact ties → the first option, counted wrong in fixtures). Chance 1/3, 1/5, 1/7; subsets labelled in-range (three, m 3), one-past-training (five, m 5), OOD in n and m (seven).

### 3.7 SWAP-MID pair law (F2)

Donor = same people, objects, h_0, o* (so the same S_0 and, under SI, identical cues), **independently redrawn swap sequence of the same length, same frame indices and same offset**; names are single tokens, so token lengths match (asserted). cf = the recipient's swaps t+1 … m applied to the donor's S_t. **Keep iff cf ∉ {own final, donor final, donor S_t}.** Kept shares (DATA-SIM): 0.485 (n 5, m 8, t 4), 0.382 (5, 4, 2), 0.454 (5, 6, 3) → ≤ 2,700 tries for 1,000 pairs; G0 asserts n_pairs = 1,000 per cell. Reported: follow_cf, stay_own, follow_dfin, follow_stale (donor S_t), and the MEAN floor (recipient's later passes with S_t := the donors' mean S_t, as `part_swap_kd`, `inject_aw_eval.py` 391-420).

## 4. Mathematical backing

Notation: n people, m swaps, τ_t = (a_t b_t), S_t = τ_t(S_{t−1}).

- **M-1 (PROVED) Pointer law.** P(S_{t−1} ∈ {a_t, b_t}) = 2/n independently of the past, so k_touch ~ Binomial(m, 2/n). S_t is a Markov chain with P_ii = 1 − 2/n and P_ij = 2/(n(n−1)); P = λI + (2/(n(n−1)))J with λ = 1 − 2/(n−1) = (n−3)/(n−1). Hence P(S_m = S_j) = 1/n + ((n−1)/n) λ^{m−j}. Consequences: n 3 has λ = 0 (after one swap the holder is uniform, independent of S_0); n 5 has λ = 1/2 (hold floor at m 8 = 0.203, matches the simulation 0.20). A perfect loop stopped at K′ < m answers S_{K′}, so the K′-curve of a perfect loop is the closed form above (unconditional); the MOVED-conditional values are DATA-SIM: K′ 4 0.202, K′ 6 0.351, K′ 7 0.562, K′ 8 1.000 at n 5 m 8; P(S_8 = S_10 | MOVED) 0.378, P(S_8 = S_12 | MOVED) 0.237.
- **M-2 (DERIVED-UNDER-ASSUMPTIONS) Complexity, conditional.** A width-5 permutation branching program decides by where one point goes (Barrington 1989), so single-pointer tracking under transposition words on n ≥ 5 is NC¹-hard (every permutation is a product of ≤ 4 transpositions); log-precision transformers of fixed depth are in uniform TC⁰ (2207.00729; 2404.08819). Assumptions: TC⁰ ≠ NC¹, log precision, m → ∞, worst case. Two limits stated: (i) padding alone stays in TC⁰ while O(logᵈ m) loops reach TCᵈ (Merrill & Sabharwal 2505.18948, theorem), so O(log m) loops suffice in principle and "m passes" is a property of this design, not of the class; (ii) for m ≤ 12 a 12-layer transformer can compose by associative scan in ⌈log₂ 12⌉ = 4 levels (2210.10749), so nothing is impossible at test lengths. **The X1 prediction is therefore a CONJECTURE about learning and length generalisation**, not a corollary.
- **M-3 (PROVED, chain rule) From per-pass fidelity to depth.** Let c_t = P(pass t's pointer correct | passes < t correct) (estimated by CWS_t, assuming the ':' readout reflects the carried pointer — DERIVED-UNDER-ASSUMPTIONS). Then P(all m passes correct) = ∏_{t ≤ m} c_t, and acc_m ≥ ∏ c_t · r, r = P(decoder reads a correct final state correctly). Prediction P-M3: a seed passes C2-1 at m 8 (≥ 0.80) only if ∏_{t≤8} CWS_t · r ≳ 0.80, i.e. mean CWS over passes 1-8 ≳ 0.973 at r ≈ 1. A seed with acc_8 > ∏ CWS_t + 0.05 is flagged DECODER-SIDE (the answer did not come through the carried pointer; read with M4).
- **M-4 (PROVED) The v0 X2 passes at chance.** On MOVED (S_m ≠ S_0, k_touch ≥ 2) "any name except S_0" scores 1/(n−1): 0.50 at n 3 vs 0.25 at n 5, a 0.25 gap with no tracking, above v0's 0.15 bar (red team F1; my simulation agrees). Normalising by the best non-tracking floor, κ = (acc − f)/(1 − f), removes every listed shortcut by construction (κ ≤ 0 for each).
- **M-5 (PROVED) Hold parity.** At hold passes the cue repeats swap m; the per-pass rule "apply τ_m" is an involution, and τ_m(S_m) = S_{m−1}. A model that re-applies the cue oscillates with period 2, which K′ 64 vs K′ 12 (both even offsets) cannot see; K′ 63 can (F13). P(S_{m−1} ≠ S_m) = 0.40 at n 5 m 4, so the oscillation costs ≥ 0.40 at odd K′.
- **M-6 (PROVED, given exact forward runs) BBH option-wise.** h_m is a bijection, so if every forward run "who has o_j after m swaps" is exact, exactly one option's run ends at X and the argmax is correct; the token prior of X cancels across options (same token, same item).
- **M-7 (DATA-SIM) Shortcut floors on MOVED** (non-tracking list: non-initial uniform, bag-of-swaps MAP, last-2-swaps MAP, last-2 only, partner of the last swap involving S_0, most frequent name, S_4 truncation): f(3, 8) 0.540, f(4, 8) 0.391, f(5, 8) 0.319, f(5, 6) 0.465, f(5, 12) 0.254 (bag-MAP binds except at 5/12). S_{m−1} (0.563 at 5/8) is **not** a floor: it needs m − 1 serial steps; it is reported as a confusion rate. MOVED shares: 0.707 at (5, 8), 0.664 at (3, 8). Build re-computes f on each cell's own items and freezes them in the registration.
- **M-8 (CONJECTURE) TH6 asymmetry.** S3 / S4 are solvable (ACC⁰ shortcuts exist, Barrington–Thérien; 2210.10749), so a one-pass learner may extrapolate farther at n 3 than n 5. Literature: solvability is a fixed-length expressivity contrast, not a length-extrapolation predictor; StateBench 2611.03094 (theorem) and 2210.10749 (shortcuts brittle for all groups) lean against one-pass extrapolation at any n; 2511.07378 gives only constant-factor length generalisation for symmetric actions. Hence an open bet at low probability.

## 6. Criteria (per seed unless stated; Wilson 95% CIs on every proportion; NEAR = the bar lies within 2 SE of the reading; Audit rules 1-5)

### 6.1 Floors (frozen at build, $0)

### 6.3 Labels

### 6.4 Pre-stated diagnostic if C2-1 fails (Literature: PAR norm drift)

## 9. Censoring (conservative; standing rule 10-14)

- VOID-RERUN once per cell for non-finite loss, OOM, host loss, drain fault (sha-verified ckpts; `host_shas.json`).

- A swap cell with n_pairs < 1,000 at eval = VOID cell = FAIL for that seed (G0 makes this a build-time impossibility).
- BBH items whose swap sentences fail to parse count as wrong (G0 asserts 750/750 parse).
